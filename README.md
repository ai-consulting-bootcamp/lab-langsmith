## Completed workflow

The notebook performs the following workflow:

1. Loads and validates the Q&A dataset, including schema, non-empty questions and answers, and topic/difficulty distributions.
2. Creates or reuses the LangSmith dataset `eu-ai-act-gdpr-qa-v1` and uploads inputs, reference answers, and metadata.
3. Runs the traced `gpt-4o-mini` target function with error handling so an individual API failure does not stop the experiment.
4. Evaluates each answer with both an LLM correctness evaluator and a deterministic reference-token F1 evaluator.
5. Runs the LangSmith experiment with two-example concurrency and collects all results.
6. Analyzes aggregate scores, topic/difficulty performance, and failed examples, then writes the evaluation report.

The Step 7 experiment prefix identifies the run as `{model}-promptv1-llmcorrectness-tokenf1`. The final analysis artifacts are written to [`outputs/`](./outputs/), including evaluator metrics, metadata-enriched results, error analysis, and the category chart.

Part 6 optionally compares two model configurations on the same dataset using the deterministic evaluator, records mean score, pass rate, latency, and a token-cap cost proxy, and writes `outputs/cost_performance_comparison.csv` plus `optimization_summary.md`.

See [`lab_proof.md`](./lab_proof.md) for the completed workflow, exact observed metrics, failure patterns, limitations, and generated artifacts.

To reproduce the workflow, install the notebook dependencies, configure `OPENAI_API_KEY` and LangSmith credentials in the environment, then run the notebook cells in order. Run Step 10 after the evaluation completes to regenerate `evaluation_summary.md` with the current scores.
